How attack detection works

Every step is a Spark job on the cluster; the labelled data lives in HDFS at /data/attacks.

01
Labelled data
1,373,724 HTTP requests marked normal or attack, from two public datasets (HttpParams, Fwaf), loaded into HDFS.
02
Clean
URL-decode, lower-case, keep only the query part (bias fix), remove duplicates and requests labelled both ways → 1,306,017.
03
Split
80% train / 20% test. Training is balanced to 4 normal : 1 attack; the test set keeps the real mix (2.9% attacks).
04
Features
Character 1-, 2- and 3-grams hashed into 3 × 4,096 buckets, plus length, special-character, digit and keyword counts, scaled 0–1.
05
Train 8 models
The Factorization Machine and 7 other Spark MLlib models learn on the same features; settings are chosen on a validation split.
06
Test and use
Scored on test requests never seen in training, repeated on 5 splits and on the other dataset, then run on every NASA URL.

How the Factorization Machine works

Our main model: FMClassifier in Spark MLlib.

ŷ = w₀ + Σi wixi + Σi<j ⟨vi, vj⟩ xixj   →   P(attack) = sigmoid(ŷ)
  • w₀ + Σ wixi is logistic regression: one weight per feature, such as the 3-gram 1=1.
  • Σ ⟨vi, vj⟩ xixj adds a weight for every pair of features. Each feature gets a short vector vi of 8 numbers, and the weight of a pair is the dot product of the two vectors.
  • So the model can learn that ', or and -- appearing together is far more suspicious than any one of them alone.
  • Storing a separate weight for every pair of 12,292 features would need about 75 million numbers. The factor vectors need 12,292 × 8 ≈ 98,000, and pairs that never appear together in training still get a sensible weight.
  • Settings, chosen on the validation split: factor size 8, step size 0.2, regularisation 10⁻⁴, 100 iterations.

One request, step by step

What the pipeline does to a typical SQL-injection attempt.

  1. Raw request/top.php?stuff=1%27%20or%201=1--
  2. URL-decode, lower-case/top.php?stuff=1' or 1=1--
  3. Keep the query partstuff=1' or 1=1--
  4. Character 3-grams (some)"1' " · "' o" · " or" · "1=1" · "=1-" · "1--"
  5. Countslength 17 · special 5 · digits 3 · keywords 0
  6. Model12,292 numbers → P(attack); above 0.5 = attack

How the settings were chosen

The Factorization Machine on the NASA logs

How to read this page. The task is supervised binary classification with 2 classes, normal and attack (SQL injection, XSS, command injection, path traversal). Models learn from labelled public datasets (HttpParams, Fwaf), because the NASA logs have no labels. F1 balances precision (when the model says "attack", how often it is right) and recall (how many real attacks it catches); accuracy alone is misleading when 97% of requests are normal.
