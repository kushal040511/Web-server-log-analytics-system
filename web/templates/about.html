Two storage zones, and why

raw is written once and never edited — it is the audit trail. curated is always regenerable from it.

That is what makes the pipeline safe to iterate on. If the parsing regex turns out to be wrong, you fix it, re-run the ETL, and nothing is lost. Every real data platform is built this way, and it is the reason the raw zone looks wastefully redundant until the first time you need it.

Why this site is deliberately dumb

Every page except SQL reads a single JSON file that Spark produced. The web service has no database connection, no query logic and no access to HDFS.

Two things follow. It cannot produce a wrong answer, because it has no logic to get wrong — every number here was computed by Spark and can be traced back to a query. And it keeps working when the cluster is shut down, which matters the morning of a demo.

The dataset, honestly

NASA-HTTP — two months of real access logs from the Kennedy Space Center web server, July and August 1995, published by the Internet Traffic Archive. Real production traffic in NCSA Common Log Format, which is what Apache still writes today.

It has a real hole in it. Four days are missing entirely — 29, 30 and 31 July, and 2 August — and the days on either side are partial. Charts here shade that gap rather than drawing a straight line across it, and no job interpolates the missing values.

There is no response-time field. So "performance" here means response weight in bytes, not latency. A live Nginx deployment would add $request_time to the log format.
